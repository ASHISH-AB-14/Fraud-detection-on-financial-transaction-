Financial Transaction Fraud Detection
A Python-based financial transaction anomaly detection project that uses
Isolation Forest to identify unusual transactions and a Flask web
dashboard to review and manage the generated alerts.
Project scope: The included transactions.csv is a small sample
dataset (500 records). The current pipeline performs unsupervised
anomaly detection. It does not train a supervised fraud-classification
model or calculate accuracy metrics.

Features
- Loads transaction data from transactions.csv.
- Preprocesses the categorical type field using one-hot encoding.
- Scales numeric features using StandardScaler.
- Applies an Isolation Forest model to flag potentially anomalous
  transactions.
- Calculates an anomaly score for each transaction.
- Exports flagged transactions to alerts.csv.
- Saves the trained Isolation Forest model and scaler in the
  artifacts/ directory.
- Provides a Flask dashboard to review alerts.
- Supports acknowledging alerts and snoozing them for 1, 6, or 24
  hours.
- Provides a JSON endpoint at /api/alerts.
- Includes a Dockerfile for container-based deployment.

Dataset
The sample transactions.csv contains 500 transaction records and these
columns:
  Column                              Description
  transaction_id                    Unique transaction identifier

  amount                            Transaction amount

  oldbalanceOrg                     Origin account balance before
transaction

  newbalanceOrig                    Origin account balance after
transaction

  step                              Transaction time-step value

  type                              Transaction type
label                             Sample dataset label (not used by
the current model for training)
The sample contains 490 records with label = 0 and 10 records with
label = 1. The current Isolation Forest pipeline does not use the
label column to fit the model.
How It Works
1. Load data: Read transaction records from the CSV file.
2. Preprocess: One-hot encode the type column, select numeric
   features, fill missing numeric values with zero, and scale the
   features.
3. Detect anomalies: Fit an Isolation Forest model. Transactions
   predicted as anomalies are marked with is_anomaly = 1.
4. Generate alerts: Save flagged transactions with their anomaly
   scores and alert-management fields to alerts.csv.
5. Review alerts: Open the Flask dashboard to inspect the generated
   alerts, acknowledge them, or snooze them.
The model uses a contamination setting of 0.02 (2%) in the current
script. This is a model parameter, not a measured fraud rate or an
accuracy score.
Run Locally (Windows)
Open Command Prompt or PowerShell and navigate to the project folder:
cd Fraud_Detection_financial_transaction
Create and activate a virtual environment:
python -m venv venv
venv\Scripts\activate
Install dependencies:
pip install -r requirements-deploy.txt
Run the detection pipeline to generate/update alerts.csv and save the
model artifacts:
python Fraud_Detection_Project.py
Start the Flask dashboard:
python app_flask_dashboard.py
Open this address in your browser:
http://127.0.0.1:5001
API Endpoint
The Flask application also exposes:
GET /api/alerts
It returns the contents of alerts.csv as JSON.
Run with Docker
Build the Docker image from the project directory:
docker build -t fraud-detection-dashboard .
Run the container:
docker run -p 5001:5001 fraud-detection-dashboard
Then open http://127.0.0.1:5001.
Important Notes and Limitations
- Isolation Forest is used for unsupervised anomaly detection. An
  anomaly is a transaction that appears unusual relative to the data;
  it is not automatically confirmed fraud.
- The label column is present in the sample CSV but is excluded from
  model training.
- No precision, recall, F1-score, or classification accuracy is
  calculated by the current project code.
- The included CSV is a small sample dataset and should not be treated
  as a production financial dataset.
- The saved scaler and model are generated by the pipeline. If the
  input data or preprocessing changes, regenerate the artifacts and
  alerts.
- This project is an educational/demo implementation, not a
  production-ready fraud prevention system.
